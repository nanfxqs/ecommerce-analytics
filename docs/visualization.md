# 图表展示与统计口径

2026-10-20，针对浏览远大于加购/购买造成曲线贴近横轴的问题，调整图表并补齐历史页面可视化。原有表格、精确指标及历史数据回放语义保留。

| 页面 | 展示方式 | 读图边界 |
| --- | --- | --- |
| 行为概览 | 浏览、加购、购买三幅联动折线，另列每日独立访客 | 日期统一 UTC，各图纵轴独立且从 0 开始；高度不能跨图比较数量，悬停同时显示当天全部原值 |
| 实时监控 | 本轮已提交结果的三幅行为折线 | 仅展示本轮已处理数据；不增加日期裁剪，不改变检查点或结果 offset |
| 购买关联 | 两项购买关联率的横向条形图 | 浏览购买交集/浏览访客、加购购买交集/加购访客，分母不同；不是要求行为先后的漏斗 |
| 分类偏好 | 已关联/unknown 覆盖环图；可切换浏览、加购、购买的分类 Top10 | 每次只画一个计数指标，切换后重新排序；unknown 用灰色保留，匿名分类 ID 不补造业务名称 |
| 用户画像 | 全范围活跃天数、最近活跃间隔两张分布图；单访客浏览分类 TopN | 群体不受分页/访客 ID 查询影响；个人图仅表示当前查询 TopN，不计算成完整分类占比 |

计数轴大数使用“万/亿”缩写；条形标签与悬浮说明保留精确数量，百分比显示两位小数。零值是真实零值，不人为设置最小柱长/扇区；没有分母或没有数据时显示空状态。所有图表随容器尺寸变化调整宽度。

## 群体分布

接口 `/api/history/profiles` 新增 `population`，原有 `total` 仍表示匹配列表的访客数。`population.total` 是所选日期范围内全部活跃访客，`scope=selected_range_all_visitors`。

- 活跃天数：1 天、2～3 天、4～7 天、8 天及以上。
- 最近活跃间隔：`[0,1天)`、`[1天,7天)`、`[7天,30天)`、`[30天,+∞)`。
- 每位访客在每张图中恰好进入一个分组；占比 = 该组访客数 / 全范围访客数。
- 最近活跃间隔 = 范围内全部访客的最新事件时间 − 该访客最后事件时间，不以今天为基准，也不直接定义为流失。
- 统计复用不可变历史 `visitor_daily`，只增加本机 DuckDB 聚合，不启动新的 Spark 作业。

全量真实历史查询核对：群体总数 **1,407,580**，活跃天数四组为 **1,263,811 / 126,176 / 14,642 / 2,951**；最近活跃四组为 **6,271 / 61,659 / 230,515 / 1,109,135**，两组分别加总到全部访客数。只有一条分页结果时，群体统计仍保持全范围。

## 验证与使用

HTTP 回归覆盖日期、分页、精确 ID、找不到访客及空范围；浏览器覆盖图表切换、全范围群体与个人查询、原有页面交互，以及百万浏览与十几次购买的极端数量级。真实全量页面另外检查图形和标签布局。

本机可复用已生成的已发布固定夹具运行（更换机器先按手动命令参考生成夹具）：

```bash
JAVA_HOME=/path/to/jdk8 PYSPARK_PYTHON=$PWD/.venv/bin/python HISTORY_TEST_STORE=$PWD/.scratch/browser-history/published uv run --frozen --extra spark --extra dev pytest tests/test_history_api.py tests/test_history_pages_api.py -q
npx --prefix frontend playwright test --config frontend/playwright.visual.config.ts
npm --prefix frontend run build
```

图表回归使用独立 8011/5181 端口，避免停止正在运行的日常演示。对照截图位于本机 `.scratch/visual-checks/`。

本次实际结果：8 项 HTTP 回归通过（含重新生成 Spark 已发布夹具），4 项 Chromium 回归通过，TypeScript/Vite 构建通过。全量历史另在独立服务上核对 1,407,580 名访客的分组加总及 7 张图的实际绘制；检查后停止了独立服务，未停止日常演示进程。本次没有重新运行 15 分钟性能验收，不将原验收数值当成本次新布局的重新测量结果。
