# 项目需求与版本范围

V1 已完成并通过验收，以下约束描述已交付的 V1。V2 为实时数据流与 React + TypeScript + Vite 页面交互升级，尚未实现；版本计划统一维护在 [路线图](roadmap.md)。

## V1：已确认并交付的约束

- 课程只明确要求使用分布式大数据组件，没有指定云产品、组件清单、数据规模或节点数。
- 优先快速完成可运行版本，时间允许后再优化。
- 在当前本地机器部署和运行。
- 没有复用限制，以快速实现为选择依据。
- V1 手动触发离线批处理，完成后刷新分析展示。
- V1 画像聚焦行为偏好与活跃程度，暂不实现年龄、地域画像。
- V1 唯一数据源为 Kaggle Retailrocket，直接进入分析链路，不转换为商城业务数据。
- V1 不依赖 campus-market；复用现有 Hadoop 环境，商城作为后续扩展。
- V1 不实现推荐算法。
- V1 由 Python 回放程序将历史行为事件写入 Kafka，保留原始事件时间；回放完成后，Spark 按本轮确定的 offset 范围批量读取并写入 HDFS，再执行离线分析。
- 商品属性与分类文件直接导入 HDFS，不经 Kafka。
- 采集按批次隔离，记录数据来源、Kafka offset 范围、记录数和处理状态；同一批次重跑不重复累计。
- 看板只读取最近一次成功发布的结果，显示批次和数据时间范围；失败批次可重试，不覆盖已发布结果。
- 技术栈采用 HDFS、YARN、PySpark / Spark SQL、Parquet、DuckDB、Streamlit 与 Plotly，运行环境与资源配置已验证并锁定，见[运行说明](operations/small-sample.md)。
- V1 提供行为概览、转化分析、商品与分类、用户画像四类页面，附数据质量摘要。
- 转化分析优先展示用户规模与交集，明确分母；不将事件数量比直接作为严格漏斗转化率。
- V1 不实现销售额、推荐模型或复杂预测。
- 转化指标限定在所选时间范围：分别统计浏览、加购、购买独立访客；浏览购买交集除以浏览访客数，加购购买交集除以加购访客数。不要求事件先后顺序，不称为严格漏斗；分母为零时显示无数据。
- 用户画像展示活跃天数、事件次数、购买次数、最近活跃时间及按浏览次数排序的分类偏好，购买行为单独展示；不使用高价值、流失预测等标签。
- 最近活跃间隔以筛选范围内最大事件时间为基准，不以机器当前时间为基准。
- 验收处理完整行为数据，开发使用固定小样本；看板支持日期筛选，时间统一为 UTC，依据原始事件时间而非回放时间。
- 分类按行为发生时间关联不晚于该时间的最近分类记录；无匹配时保留为未知分类，不使用未来记录补齐，展示分类关联覆盖率。
- 无法解析时间、缺少访客或商品标识、行为类型不合法的记录隔离并统计，不进入正式指标；原始数据保留。浏览、加购缺少交易标识属于正常情况。
- 采集重试造成的同一源记录重复只计一次；源文件中内容相同但位于不同行的记录保留，报告疑似重复数量。
- 日期筛选统一影响全部页面及画像；最近活跃间隔以筛选范围内最大事件时间为基准，无行为访客不进入当前画像列表。画像支持访客 ID 查询和分页。

## V1：已完成验证

- 数据集已从官方来源下载，验收时无需认证；登记文件校验值与行数，凭据不入库。
- 三节点集群、网络、磁盘与 YARN 资源经过实际核查，完成全量跨节点计算。
- Java、Python、Spark 与 Kafka 连接器兼容环境已锁定；全量数据、重算、发布保护和看板通过验证。

详见[全量验收证据](evidence/full/README.md)和[已实现架构](architecture.md)。

## V2：规划中的扩展

V2 计划增加清洗前的原始流监控、清洗后的质量与业务统计更新，以及 React + TypeScript + Vite 页面交互。历史回放标识、UTC 业务时间、去重、异常隔离、访客指标口径和已验证结果保护继续沿用 V1。

具体组件、流处理状态与恢复机制、接口以及更新频率尚待详细设计和验收，见[路线图的 V2 范围](roadmap.md#v2实时数据流与-react-页面交互规划中)。这不是 V1 已具备的能力。
