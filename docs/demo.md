# 课程答辩与项目演示

日常只用根目录的 `./demo`。不用分别开 API、前端，也不用现场输入 SSH、Spark、发布等命令。

## 1. 答辩前准备

在项目根目录运行：

```bash
./demo
```

首次启动会创建 `.demo/config.json`，校验并复制本机已发布的全量历史快照，再调用相邻 `hadoop-cluster` 仓库的原启动脚本启动三台虚拟机、Hadoop 和 Kafka。随后启动 API、构建页面，并打印就绪地址：**http://127.0.0.1:5173**。开机后首次启动可能需要几分钟，提前十分钟运行，等终端显示“演示已就绪”。

本机已验收的历史输入位于 `~/.cache/retailrocket-published`；入口只将当前不可变快照复制到 `.demo/published`，不会修改原存储。后续新的历史发布只切换演示副本的指针。`.demo` 在项目目录内持久保留，不依赖重启会清空的 `/tmp`。

打开网页后先确认完整历史结果：浏览 **2,664,312**、加购 **69,332**、购买 **22,457**、访客 **1,407,580**。默认没有日期过滤时才能与全量数直接比较。不要在正式上台前启动完整数据回放。

实时页可能保留上次已提前停止的轮次，这是正常留存。点击“启动回放”会创建独立新轮次，不必删除旧状态；只有“待恢复”的未结束轮次需要先处理恢复。

## 2. 建议演示顺序（约 6–8 分钟）

1. **交代数据来源。** 这是 Retailrocket 历史数据回放，不是商城此刻真实访问；业务日期使用原始事件 UTC，处理时间是本次回放时间。
2. **启动小样本。** 打开“实时监控”，选固定小样本、速率 **5 条/秒**，只点击一次“启动回放”。首次启动 Spark 可能等待约一分钟，可先切到历史分析讲解；不要因数值暂时没变化反复启动。
3. **展示历史分析。** 行为概览 → 购买关联 → 分类偏好 → 用户画像 → 数据质量。选一个日期范围，说明筛选联动、访客跨日去重及零分母“无数据”。画像用表格中已有的访客 ID 查询，避免临场猜 ID。
4. **回到实时监控。** 指出 Kafka 累计物理消息、源游标、各分区末端/已提交 offset、积压，以及有效事件、访客、UTC 日趋势、质量统计和最多 20 条原始样本。
5. **暂停 → 继续。** 点“暂停发送”，等实际确认；发送停止，但 Spark 继续消化积压。等十几秒观察积压下降，再点“继续发送”，同一轮次从原位置继续。
6. **提前停止。** 点“提前停止”，等积压为 0、状态变为提前停止/结果不完整。说明它不会自动发布成完整历史；历史页面仍是此前已成功发布的完整批次。
7. **说明完整链路。** 正常发完所选范围后，系统先释放流资源，再自动历史分析、导出、校验、原子发布。展示[验收记录](operations/v2-acceptance.md)，不在几分钟答辩里重新跑完 275 万条。

固定小样本有 **10,000 条**，5 条/秒发完约需 **33 分钟**，另有启动、排空和历史分析时间。因此短答辩用暂停/继续/提前停止演示，完整自动发布使用已经留存的真实验收证据讲解。不要将提前停止称为完整回放。

已验收性能为对应正常小样本 profile 下连续约 903 秒、约 5 条/秒、4492 条全部实际 ACK 可追踪，P95 保守上界 **8.58 秒**；不是全量突发速率下的延迟承诺。

## 3. 演示结束

在另一个终端、项目根目录运行：

```bash
./demo stop
```

入口会对运行中或暂停的轮次请求提前停止，等待积压为 0、流资源释放；已进入历史分析/发布则等待完成。随后关闭本次网页与 API，调用集群停止脚本按依赖顺序停止服务，最后通过 libvirt 正常关闭三台项目虚拟机。重复执行会跳过已经关闭的虚拟机，不删除数据、历史快照或检查点。

轮次失败、待恢复、排空超时或服务停止失败时会报错，不继续关闭虚拟机。先在页面恢复/处理原轮次，再重试；不强制断电。排空/发布最多等待 15 分钟，关机最多等待 3 分钟。若部分虚拟机已经关闭导致集群停止脚本无法连接，请检查集群状态后处理，不跳过错误。

只想关闭网页和 API、保持集群运行时，仍可在启动终端按 **Ctrl+C**（先在页面停止轮次并等积压为 0）。只关闭浏览器不会停止后台任务。若直接中断启动终端时仍有活动轮次，下次启动需在页面人工恢复原轮次。

## 4. 现场备用：不启动集群

```bash
./demo --history-only
```

可在不启动虚拟机、Kafka、YARN 的情况下展示已有真实历史结果。此模式不注册回放控制，演示历史分析导航即可，不能宣称正在采集。这是现场网络或虚拟机不可用时的备用方式。

## 5. 本机配置与首次安装

本机配置为 `.demo/config.json`，不提交 Git；模板是 `config/demo.example.json`。一般无需修改：

| 字段 | 用途 |
| --- | --- |
| `store` | 演示独立发布存储，默认 `.demo/published` |
| `seed_store` | 首次复制的已发布数据来源，默认 `~/.cache/retailrocket-published` |
| `cluster_config` | 本机 SSH worker 配置路径；设为 `null` 默认只展示历史 |
| `cluster_start_script` | 既有集群启动脚本；设为 `null` 则由操作者提前启动集群与 Kafka |
| `cluster_stop_script` | 默认 `../hadoop-cluster/stop-cluster.sh`，停止服务后才关机 |
| `cluster_vms` | 默认 `vm-hadoop01`、`vm-hadoop02`、`vm-hadoop03`；只关闭这些项目虚拟机 |
| `api_port` / `web_port` | 默认 8000 / 5173，只监听本机；冲突时明确退出，不强杀占用者 |

cluster 模板 `config/demo-cluster.example.json` 对应这台机器已准备好的 `h1` 和持久 edge 数据目录。它不是通用安装器，不重新下载数据或部署运行时；换机器应按[回放部署说明](operations/replay.md)准备 worker、固定输入和参考数据后更新配置。正常 profile 的分区数/检查点参数不能临场修改。

新检出或依赖缺失时，只做一次：

```bash
uv sync --frozen
npm --prefix frontend ci
./demo
```

运行需要 Python 3.11/3.12、Node/npm、SSH，以及已安装的 edge 运行时。依赖已装好时，入口不联网安装依赖；页面每次启动重新构建，避免展示旧前端。自定义配置可用 `./demo --config /path/to/config.json`。

## 6. 常见问题

| 现象 | 处理 |
| --- | --- |
| 启动集群失败 | 看 `.demo/logs/cluster.log`，检查 libvirt 和 SSH；现场先用离线备用模式 |
| Kafka 启动失败 | 看 `.demo/logs/kafka-h1.log` 等，使用已有配置排查，不替换集群配置 |
| 历史结果不可用 | 看 `.demo/logs/api.log`，核对 `seed_store/current.json` 和对应不可变批次；不要手改指针 |
| 初次副本中断 | 停止入口，将 `.demo/published` 移到另一个备份目录后再启动；不要动原 `seed_store` |
| 端口被占用/重复启动 | 关闭自己的原启动终端，或在本机配置换端口；不要随便 kill 其他服务 |
| 页面构建失败 | 看 `.demo/logs/build.log`，确认 npm 依赖已安装 |
| 回放长时间无变化 | 看页面错误、积压和各 offset，查 `.demo/logs/api.log`；初次 Spark 启动需要等待 |
| 显示待恢复 | 点击恢复原轮次，不删除检查点；历史阶段失败使用对应历史发布重试 |

所有入口日志保存在 `.demo/logs/`，轮次镜像位于 `.demo/replay-runs/`。日志追加保留，不自动删除。
