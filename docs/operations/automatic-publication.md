# 正常回放后的完整历史分析与发布

正常回放完成后，后台先确认最终 Kafka 范围已由结果和检查点覆盖、保存最终实时结果并释放流进程，再确认该流 YARN 应用为 FINISHED/SUCCEEDED。随后进入等待历史分析、完整分析、导出、校验发布阶段。整个阶段占用同一回放轮次，新回放不能抢占；页面刷新或关闭不影响后台作业。提前停止的轮次不进入此流程。

本机 cluster 配置继续使用启动回放的配置。edge 配置增加经过核对的参考数据来源及三个文件的 SHA256：

```json
{
  "reference_source": "/operator/projected-references",
  "reference_sha256": {
    "references.json": "<64位SHA256>",
    "categories.csv": "<64位SHA256>",
    "category_tree.csv": "<64位SHA256>"
  }
}
```

参考来源必须已经由原始属性文件生成，保留原始文件的校验和与行数。系统验证投影文件未变化，再为所选已注册事件范围生成不可变绑定：小样本和完整数据分别使用精确匹配其事件 manifest 的 `events_input`。相同源版本、文件及校验和下，小样本可使用完整分类参考表，原始参考文件行数保持不变。不同来源或不连续范围拒绝绑定，不通过放宽发布校验适配部分数据。

绑定只准备一次，保存在 edge 轮次根目录旁的 `reference-bindings` 及 HDFS references 下的独立版本目录，重用前核对文件与元数据。输入与共享参考不属于单轮清理范围。批处理输出固定为 `hdfs://mycluster/retailrocket/batches/<run-id>`，edge 导出固定在本轮目录的 `export`，日志、应用证据及批处理状态也保存在本轮目录。

实际分析使用既有 YARN 批处理命令和固定 Kafka offset 范围；已完整落盘的 raw 可在失败重试中复用，源记录仍按 V1 口径去重。完成后通过既有导出脚本检查 `_SUCCESS`，将导出与 replay manifest 传回本机新的轮次产物目录。导出解包拒绝链接、路径穿越及非普通文件。只有本机完整发布校验成功后，才原子切换当前历史批次。历史页面在此之前继续展示此前成功结果。

页面展示各阶段、YARN 批处理应用、已发布批次及 revision。分析、传输或校验失败后保留此前成功批次和本轮证据，阻止下一轮抢占；由操作者点击“重试历史分析与发布”，不会无限自动重启失败作业。已成功导出的批次不重复提交 Spark，已落盘的完整 raw 可供分析重试，原子发布重试不会重复累计。API 重启后的人工恢复仍遵循回放恢复约定；历史失败轮次使用历史重试操作。

未完成的 raw 写入、损坏的参考绑定或导出会明确失败并保留产物，需要先核对证据和修复存储，不能删除当前发布指针、改源范围或将提前停止结果改成完整结果来绕过校验。
