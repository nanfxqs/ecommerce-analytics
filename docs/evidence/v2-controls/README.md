# 回放控制真实链路验收

2026-10-19，实际 Chromium 页面通过本机 HTTP、真实 SSH adapter、独立 edge worker 控制 Kafka/YARN/HDFS。小样本范围为 61 个已校验源记录，速率设置 2 条/秒。浏览器完整测试通过，耗时约 149 秒（包含集群冷启动、消费及观测等待），没有模拟 HTTP 或集群。

[smoke.json](smoke.json) 保存三个实际观测：

- paused：确认发送 23，源游标 23，积压 23；后台确认暂停。
- drained：仍暂停，确认量和源游标仍为 23，消费者已提交检查点推进、积压降为 0。说明暂停没有暂停消费。
- stopped：从相同游标继续后确认 24，提前停止后积压为 0、`phase=stopped`、`early_stopped=true`、`complete=false`、`stream_released=true`。没有将部分轮次作为完整历史结果发布。

浏览器使用“启动回放”“暂停发送”“继续发送”“提前停止”操作，并验证页面刷新后仍显示提前停止且不完整。另一次真实轮次暂停 24/61 并等待积压清零后，以 `python -m retailrocket.replay_control stop` 成功停止并释放资源，验证命令行走相同控制边界。

HTTP 集成测试覆盖同一轮次控制、重复操作、无效状态及慢集群观测不能覆盖新控制确认；控制测试 2 项、既有启动/参数测试 2 项全部通过。前端构建通过。测试未宣称达到性能门槛；流状态算法和快速观测由后续持续统计任务验证。
